# סופר ומונה — עזרה ושאלות נפוצות

מסמך עזרה מובנה בתוכנה · עברית · עודכן ב־15.10.2026.

ההסברים מתייחסים לקוד הנוכחי של גרסת **0.6.0 בפיתוח**, לרבות שינויים שטרם הופצו. בגרסה ישנה ייתכן שחלק מהאפשרויות עדיין אינן מופיעות. שמות הכפתורים מובאים לפי הממשק העברי; המיקום והפריסה עשויים להשתנות לפי גודל המסך וערכת העיצוב.

למתחילים כדאי לקרוא תחילה את „צעדים ראשונים”, „פרויקטים” ו„כתיבה וטיימר”. לפתרון בעיה אפשר לחפש במסמך מילים מן ההודעה שמופיעה בתוכנה.

## צעדים ראשונים

<a id="start-purpose"></a>
### למה משמשת סופר ומונה?

התוכנה מסייעת לתעד כתיבת סת״ם: מה נכתב, באיזה פרויקט, כמה זמן הושקע ומהי ההתקדמות. היא כוללת גם יעדים, תכנון, חישובי רווחיות, הוצאות, תשלומים, הזמנות, מעקב הגהה ודוחות. איכות הכתיבה והכשרות אינן נבדקות על ידי התוכנה.

<a id="start-account"></a>
### האם צריך להירשם או לשלם?

אין צורך בחשבון משתמש, בהרשמה או בתשלום כדי להשתמש בתוכנה. הנתונים נשמרים במכשיר שבו עובדים. במסך „אודות” יש אפשרות לתמוך בפיתוח באמצעות תרומה.

<a id="start-offline"></a>
### האם אפשר לעבוד בלי אינטרנט?

כן. תיעוד כתיבה, טיימר, סיכומים וחישובים פועלים מקומית. בדיקת עדכונים והורדתם דורשות חיבור לרשת. פתיחת אתר, שליחת דואר או שיתוף דרך שירות חיצוני תלויים בשירות שבחרת.

<a id="start-platforms"></a>
### באילו מכשירים אפשר להשתמש?

פלטפורמות ההפצה של הפרויקט הן Android 7.0 ומעלה ו־Windows 10 ומעלה. המדריך מתייחס לשתיהן. חלון צף וקיצורי מקלדת מתוארים בהמשך כאפשרויות של גרסת המחשב.

<a id="start-first-session"></a>
### איך מתחילים לכתוב בפעם הראשונה?

פתח „פרויקטים”, צור פרויקט ובחר את סוג העבודה והמבנה שלו. חזור למסך הכתיבה ובחר את הפרויקט. במצב חכם ודא שהמיקום נכון, התחל את הטיימר ולחץ „סיימתי שורה” אחרי כל שורה שהושלמה. ביציאה להפסקה השתמש בכפתור ההפסקה; כשסיימת את הישיבה לחץ „סיום כתיבה”.

<a id="start-modes"></a>
### מה ההבדל בין מצב חכם, מצב רגיל והזנה ידנית?

במצב חכם אתה מסמן כל שורה שהסתיימה, והתוכנה שומרת התקדמות ומקדמת מיקום. במצב רגיל הטיימר מודד את זמן הישיבה, ובסיום אתה מזין מה נכתב. בהזנה ידנית אתה רושם עבודה שכבר נעשתה, עם תאריך וזמן אם הם ידועים. שלוש הדרכים מעדכנות את אותה היסטוריית עבודה.

<a id="start-away-from-device"></a>
### אני כותב בלי מחשב לידי. איך כדאי לתעד?

אפשר להשתמש בהזנה ידנית או לפתוח „כלים” ואז „יומן כתיבה” ולהזין את העבודה לפי ימים. ביומן אפשר גם להדפיס טבלה ריקה, למלא אותה על נייר ולהעתיק אחר כך לתוכנה. הנתונים שעל הנייר ייכנסו לסיכומים רק לאחר הזנה ושמירה.

<a id="start-navigation"></a>
### איפה נמצאים הכלים וההסברים הראשוניים?

כפתור „כלים” במסך הבית פותח את יומן הכתיבה, ההזמנות, לוח ההספקים, הדוחות, מעקב ההגהה ומחשבון הצעת המחיר. אל ההוצאות וסל המחזור אפשר להגיע ממסך הפרויקטים. כדי לקרוא שוב את ההסבר הראשוני פתח „הגדרות” ואז „מסך הפתיחה”.

## פרויקטים ומרכז הפרויקט

<a id="project-purpose"></a>
### למה צריך לפתוח פרויקט לפני שרושמים עבודה?

הפרויקט מגדיר למה שייכת הכתיבה, מהי יחידת העבודה, כמה עבודה הוזמנה ומה המחיר. בלי הפרטים האלה אי אפשר לפרש נכון שורה, עמוד, מזוזה או פרשייה. אפשר לפתוח כמה פרויקטים ולעבור ביניהם לפי העבודה בפועל.

<a id="project-create"></a>
### איך יוצרים פרויקט ומה חייבים למלא?

במסך „פרויקטים” בחר „פרויקט חדש”. הזן שם, בחר ספר תורה, מגילה, מזוזה או תפילין ומלא את המבנה והשדות הנדרשים בטופס. הזן מחיר מספרי; אם כרגע נדרש מעקב כתיבה בלבד אפשר להזין 0. אימייל לקוח ותאריך יעד הם שדות רשות.

<a id="project-price-unit"></a>
### האם המחיר הוא לעמוד או לכל העבודה?

בספר תורה המחיר והוצאות הבסיס הם לעמוד; במזוזות — למזוזה; בתפילין — לזוג הכולל ראש ויד; ובמגילה — לכל הפרויקט. בדוק את כותרת „כספים” מעל השדות לפני השמירה. למשל, מחיר של ספר שלם אינו מתאים לשדה שמוגדר „לעמוד”.

<a id="project-center"></a>
### מה יש במרכז הפרויקט?

לחיצה על פרויקט פותחת את „מרכז הפרויקט”. „סקירה” מציגה התקדמות ונתוני סיכום, „הכתיבה” מאפשרת לבדוק ולתקן את העבודה לפי יחידות או רשומות, ו„פרטים” מציגה את פרטי ההזמנה והמבנה. ניתן לערוך את הפרטים מתוך המרכז.

<a id="project-edit"></a>
### האם אפשר לשנות פרטי פרויקט אחרי שהתחלתי?

כן. פתח את מרכז הפרויקט ובחר בעריכת הפרטים. אפשר לעדכן, למשל, שם, מחיר, הוצאות, יעדים ופרטי לקוח. שינוי מחיר או הוצאות יכול לשנות את הסיכומים המחושבים לפי פרטי הפרויקט; זו אינה מערכת שמקבעת חשבונית לכל ישיבה.

<a id="project-structure"></a>
### מה קורה אם משנים את מספר העמודים או השורות?

המבנה משפיע על ההתקדמות, טווחי הכתיבה וצפי הסיום. לפני שינוי משמעותי מוצגת הודעת השפעה. רשומות חדשות שומרות את מבנה העמוד בזמן הרישום, אך רשומות ישנות שחסר בהן המידע עשויות להיות מחושבות מחדש. קרא את ההודעה ובצע גיבוי לפני שינוי מבנה של עבודה קיימת.

<a id="project-select"></a>
### איך מחליפים פרויקט בזמן העבודה?

בחר את הפרויקט הרצוי בבורר הפרויקטים במסך הכתיבה. אם יש ישיבה פעילה, סיים ושמור אותה לפני מעבר לפרויקט אחר. כך הזמן והמיקום נשארים משויכים לעבודה הנכונה. התוכנה חוזרת בדרך כלל לפרויקט האחרון שנבחר.

<a id="project-existing-work"></a>
### איך מכניסים פרויקט שכבר כתבתי חלק ממנו לפני התקנת התוכנה?

צור את הפרויקט עם מלוא היקף העבודה, ואז הזן את החלק שכבר נכתב. אם ידועים התאריכים והזמנים אפשר לרשום אותם. אם מדובר בהשלמת עבר ללא תאריך, בחר „ללא תאריך (כללי)”: העבודה תיכלל בהתקדמות, אך לא ברווח, בממוצעים או ביעד היומי.

## כתיבה, טיימר והפסקות

<a id="timer-start"></a>
### מה לבדוק לפני שמפעילים את הטיימר?

בדוק שנבחר הפרויקט הנכון ושמצב העבודה מתאים לך. במצב חכם בדוק גם את העמוד והשורה, או את המזוזה או פרשיית התפילין. המיקום המוצג הוא המקום שממנו התוכנה תייחס את הכתיבה הבאה.

<a id="timer-two-clocks"></a>
### מה ההבדל בין „זמן כתיבה” ל„זמן השורה”?

„זמן כתיבה” מודד את זמן הכתיבה נטו בישיבה הנוכחית. „זמן השורה” מודד את הזמן שהושקע בשורה הנוכחית, בלי הפסקות. במצב חכם הוא יכול לכלול גם זמן מישיבה קודמת שנעצרה באמצע אותה שורה, ולכן לפעמים הוא גדול מזמן הישיבה החדשה.

<a id="timer-smart-line"></a>
### מה נשמר בלחיצה על „סיימתי שורה”?

במצב חכם הלחיצה רושמת שורה שהושלמה, משייכת לה את זמן הכתיבה ומעדכנת את ההספק והמיקום. אין צורך להמתין לסיום הישיבה כדי שהשורות שסומנו יישמרו. יש ללחוץ פעם אחת לכל שורה שהושלמה בפועל.

<a id="timer-regular-line"></a>
### למה במצב רגיל כתוב „איפוס זמן שורה”?

במצב רגיל הלחיצה מאפסת רק את שעון השורה לצורך מעקב אחר הקצב. היא אינה מוסיפה שורה להספק ואינה מקדמת מיקום חכם. את כמות העבודה מזינים בטופס הסיכום בסיום הישיבה.

<a id="timer-break"></a>
### איך יוצאים להפסקה וחוזרים לכתיבה?

לחץ על כפתור ההפסקה כשאתה מפסיק לכתוב, וחזור באמצעות כפתור ההמשך. זמן ההפסקה נמדד בנפרד ואינו מתווסף לזמן הכתיבה או לזמן השורה. בחירת משך להפסקה משמשת למעקב ולהתראה; היא אינה מחזירה אותך לכתיבה באופן אוטומטי.

<a id="timer-break-question"></a>
### איך מבטלים את השאלה „כמה זמן ההפסקה”?

פתח „הגדרות” ואז „תוספות למסך הבית”, וכבה את „לשאול כמה זמן ההפסקה”. ההפסקה עצמה עדיין פועלת ונמדדת. אם בחרת משך ועברת אותו, מוצגת החריגה כדי שתוכל לראות כמה התארכה ההפסקה.

<a id="timer-background"></a>
### האם סגירת החלון או מעבר לאפליקציה אחרת עוצרים את הזמן?

לא. הטיימר מסתמך על זמני התחלה שנשמרים ויכול לחשב את הזמן גם לאחר חזרה לתוכנה. גם הפסקה פעילה ממשיכה להימדד. כשאתה מפסיק לעבוד, לחץ על הפסקה או סיום; עצם סגירת החלון אינה הודעה לתוכנה שהפסקת לכתוב.

אם שכחת להפעיל הפסקה, לפני פעולת השורה או סיום הכתיבה תוצג שאלת „זמן שורה חריג” כשהזמן שטרם אושר הוא לפחות 25 דקות וגם פי חמישה מהשורה הקודמת, או שעה ומעלה גם בלי שורה קודמת. „כן, שמור את הזמן” מאשר את המדידה וממשיך בפעולה שביקשת. „התחל מדידה מחדש” מעביר רק את זמן השורה הנוכחית להפסקה ומתחיל למדוד מחדש באותו מיקום; שורות וזמן שכבר נשמרו נשארים. „ביטול” משאיר את הזמן ללא שינוי. זמן ההמתנה באישור אינו נספר ככתיבה.

<a id="timer-finish-partial"></a>
### סיימתי ישיבה באמצע שורה. מה לעשות?

במצב חכם לחץ „סיום כתיבה”. כברירת מחדל נשמר הזמן של השורה החלקית, והמיקום נשאר באותה שורה. הזמן נכלל בזמן העבודה, אבל עדיין לא מתווספת שורה להספק. כשתחזור לאותה שורה ותשלים אותה, היא תיספר פעם אחת בלבד.

<a id="timer-partial-dates"></a>
### כתבתי חצי שורה אתמול והשלמתי היום. לאיזה יום היא שייכת?

הזמן שהושקע בכל יום נשאר באותו יום עבודה. השורה כהספק נרשמת בעת ההשלמה. למשל, 3 דקות אתמול ו־2 דקות היום הן 5 דקות עבודה על שורה אחת, ולא שתי שורות. לכן ביום הראשון אפשר לראות זמן כתיבה בלי שורה שלמה נוספת.

<a id="timer-finish-completes"></a>
### אני תמיד עוצר בסוף שורה. אפשר שהסיום יסמן גם את השורה?

כן. ב„הגדרות” ואז „תוספות למסך הבית” אפשר להפעיל „סיום כתיבה משלים שורה”. במצב חכם הסיום ישלים את השורה ויקדם את המיקום. הפעל זאת רק אם זה הרגל העבודה שלך: כשהאפשרות פעילה, עצירה באמצע שורה עלולה לרשום אותה כשלמה.

<a id="timer-line-then-stop"></a>
### אפשר ללחוץ „סיימתי שורה” ומיד „סיום כתיבה”?

כן. אם שמירת השורה עדיין מתבצעת, בקשת הסיום ממתינה לה ומסיימת אחריה. ברצף הזה התוכנה אינה אמורה להשלים גם את השורה הבאה. בדוק לאחר הסיום שהמיקום וההספק תואמים למה שנכתב.

<a id="timer-forgot-line"></a>
### שכחתי לסמן כמה שורות במצב חכם. איך משלימים את הדיווח?

אפשר לעבור למצב רגיל במהלך הישיבה ולאשר את המעבר. השורות שכבר סומנו נשארות, ובסיום טופס הסיכום מקבל רק את הזמן שטרם שויך להן. הזן בו את השורות שעדיין לא נרשמו, בלי לכלול שוב את השורות שכבר נשמרו במצב חכם.

<a id="timer-switch-mode"></a>
### למה אי אפשר לעבור מרגיל לחכם באמצע ישיבה?

במצב רגיל עדיין לא הוזן מה נכתב, ולכן אין לתוכנה מיקום בטוח שממנו תוכל להמשיך אוטומטית. סיים ושמור את הישיבה, החלף לחכם ובדוק את המיקום לפני התחלה חדשה. כשהטיימר כבוי אפשר להחליף מצבים ללא אישור מעבר.

<a id="timer-forgot-stop"></a>
### שכחתי לעצור את הטיימר והוא רץ זמן רב. איך מתקנים?

סיים את הישיבה ובדוק את רשומותיה בהיסטוריה. תקן את זמני הרשומות שאינם משקפים כתיבה בפועל. במצב חכם ייתכן שחלק מהזמן כבר שויך לשורות וחלק נשמר כמקטע שורה חלקית; מקטע חלקי אינו נערך כטווח כתיבה רגיל, וניתן למחוק רישום זמן שגוי שלו.

## הזנה ידנית והשלמת רישומים

<a id="manual-open"></a>
### איך רושמים כתיבה שנעשתה קודם?

פתח „הזנה ידנית” ממסך הכתיבה, או בחר את היום המתאים ביומן הכתיבה. בחר פרויקט, מלא מה נכתב, קבע תאריך והזן זמן אם ידוע. שמור רק לאחר בדיקת הפרויקט, טווח הכתיבה והתאריך.

<a id="manual-time-modes"></a>
### איך מזינים את זמן העבודה?

אפשר להזין משך כולל, או לבחור „משעה עד שעה”. משך כולל מתאים כשידוע כמה זמן עבדת נטו; שעות התחלה וסיום מתאימות כשידוע טווח השעות. אם היו הפסקות, ודא שאינך מציג את כל טווח השעות כזמן כתיבה נטו — אפשר לפצל למקטעי כתיבה.

<a id="manual-midnight"></a>
### איך רושמים עבודה שהסתיימה אחרי חצות?

במצב „משעה עד שעה” בחר שעת התחלה ושעת סיום ובדוק את הסימון „למחרת” ואת משך העבודה המחושב. אל תשמור רק על סמך השעות: ודא שגם התאריך והמשך המוצגים נכונים. שיוך יום העבודה מושפע גם מהגדרת „מעבר יום”.

<a id="manual-no-time"></a>
### אני יודע מה כתבתי ובאיזה יום, אבל לא כמה זמן. אפשר לרשום?

כן. בחר תאריך ורשום את העבודה בלי שעות. היא תוכל להיכלל בהספק ובהתקדמות המתאימים, אך לא תשמש כאילו נכתבה באפס דקות. ממוצעי זמן ושכר לשעה מבוססים על רשומות שנמדד בהן זמן.

<a id="manual-no-date"></a>
### מה ההבדל בין „ללא תאריך” לבין עבודה בלי זמן?

„ללא תאריך (כללי)” משמש להשלמת הספק עבר: העבודה נכללת בהתקדמות, אך אינה נכנסת לממוצעים, לרווח או ליעד של יום מסוים. רשומה עם תאריך ובלי זמן משויכת ליום ידוע; רק מדידת הזמן חסרה בה. בחר באפשרות שמתארת את המידע שבאמת ידוע לך.

<a id="manual-page-range"></a>
### איך מזינים חלקי עמודים או טווח שחוצה עמוד?

הזן „מעמוד”, „עד עמוד”, „משורה” ו„עד שורה”. אם „עד עמוד” ריק, מדובר בעמוד בודד. בעמוד של 42 שורות, טווח מעמוד מג שורה 1 עד עמוד מד שורה 21 הוא 63 שורות. הזמן מתחלק בין העמודים ביחס למספר השורות בכל אחד.

<a id="manual-hebrew-pages"></a>
### אפשר להזין מספרי עמודים באותיות עבריות?

כן. שדות העמודים מקבלים מספר או אותיות עבריות, למשל 43 או מג. ודא שהעמוד נמצא בתוך גבולות הפרויקט ושטווח השורות תואם למספר השורות שהוגדר לעמוד.

<a id="manual-add-another"></a>
### מה ההבדל בין „הוסף עוד” לבין „שמור וסגור”?

„הוסף עוד” שומר את ההזנה הנוכחית ומשאיר אפשרות להזנה נוספת. „שמור” או „שמור וסגור” מסיימים את ההזנה וסוגרים את הטופס. אם הטופס נפתח מסיכום טיימר וזמן הישיבה כבר נשמר בהזנה הראשונה, הוא לא אמור להיספר שוב בהזנה הבאה; בדוק את הודעת הזמן בטופס.

<a id="manual-save-error"></a>
### לחצתי שמירה והטופס נשאר פתוח. מה לבדוק?

גלול לראש תוכן הטופס וחפש הודעת שגיאה. בדוק פרויקט נבחר, תאריך ושעות, מספרים תקינים, טווח שורות וחפיפה לעבודה קיימת. בזמן שמירה הכפתורים ננעלים זמנית. אם מופיעה שגיאת אחסון, טפל בה לפי ההודעה ונסה שוב; אל תניח שהטופס נשמר רק מפני שלחצת.

<a id="manual-recovery"></a>
### התוכנה נסגרה באמצע טופס הסיכום. האם אפשר להמשיך?

בסיום ישיבה רגילה נשמרת טיוטת התאוששות של זמן הישיבה. בהזנה ידנית נשמרת טיוטה בעת ניסיון שמירה, לפני בדיקת השדות. טיוטה שלא הושלמה יכולה להיפתח שוב בהפעלה הבאה. שדות שהוקלדו בלי ניסיון שמירה אינם מובטחים לשחזור, וביטול מפורש של ההזנה מוחק את הטיוטה.

## ספר תורה ומגילה

<a id="paged-position"></a>
### איך משנים עמוד או שורה במצב חכם?

לחץ על המיקום הגדול או על שם הפרשה שמופיע במסך הכתיבה ובחר את המקום הרצוי. שינוי מיקום קובע היכן תמשיך הכתיבה; הוא אינו מזין אוטומטית את העמודים שדילגת עליהם. עבודה קודמת שטרם נרשמה יש להזין בנפרד.

<a id="paged-map"></a>
### איך רואים מה כבר נכתב בכל עמוד?

פתח את מרכז הפרויקט ועבור אל „הכתיבה” או אל „מפת העבודה” שבסקירה. כל עמוד מוצג כיחידה נפרדת וניתן לפתוח גם עמוד שטרם נכתב. מתוך עמוד אפשר לבדוק את השורות הרשומות ולתקן רישום שגוי.

<a id="paged-skip"></a>
### למה המיקום קפץ מעבר לעמוד או לכמה שורות?

בספר תורה ובמגילה המצב החכם מחפש את המיקום הפנוי הבא. עמוד מלא שכבר נרשם מדולג, ובעמוד חלקי נבחר הפער הראשון שטרם נרשם. קרא את הודעת הדילוג ובדוק את ההיסטוריה אם אינך זוכר שהעבודה כבר הוזנה.

<a id="paged-overlap"></a>
### מה פירוש אזהרה שהשורות כבר נכתבו?

קיים רישום המכסה את הטווח שביקשת להזין. ייתכן שכבר סימנת אותו במצב חכם, הזנת אותו ידנית או ייבאת אותו מגיבוי. בדוק את העמוד במרכז הפרויקט ותקן את הרישום השגוי לפני הזנה נוספת. שינוי המיקום בלבד אינו מוחק רישום קודם.

<a id="megillah-formats"></a>
### אילו מבנים של מגילה קיימים?

ביצירת פרויקט מגילה ניתן לבחור 11 שורות ו־38 עמודים, 21 שורות ו־20 עמודים, או 28 שורות ו־16 עמודים. המעקב הוא לפי העמודים והשורות של המבנה שנבחר. קיימת גם אפשרות מיוחדת של 14.5 שורות, שמוסברת בשאלה הבאה.

<a id="megillah-special"></a>
### בחרתי מגילה של 14.5 שורות והאחוז מעל 100%. למה?

זהו מסלול מיוחד שנוסף לבקשת בעל הפרויקט, עם 399 עמודים ו־15 שורות שלמות לבחירה ברישום. אחוז ההתקדמות המוצג בו מתחיל אחרי תחילת הכתיבה קרוב ל־150% ויורד עד 100%. זהו חיווי מיוחד, לא מדד רגיל; יתרת העבודה והחישובים הכספיים ממשיכים לפי ההתקדמות האמיתית.

<a id="megillah-profit"></a>
### איך מחושב הרווח במגילה שנכתבה בחלקה?

מחיר המגילה והוצאות הבסיס מוגדרים לכל הפרויקט. הרווח המחושב נצבר לפי החלק שנכתב: אם נכתבו 10% מהעבודה, נזקפים 10% מהמחיר בניכוי הוצאות הבסיס. לצורך זמן משתמשים בשורות הפיזיות; בסיס של 420 שורות בהשוואת מחירים הוא יחידת השוואה ואינו משנה את מספר השורות במגילה.

## מזוזות

<a id="mezuza-lines"></a>
### לפי כמה שורות מחושבת מזוזה?

מזוזה מחושבת בתוכנה לפי 22 שורות. אפשר לרשום מזוזות שלמות או התקדמות במזוזה חלקית. לכן חלק מהסיכומים יכולים להציג שבר של מזוזה, בהתאם למספר השורות שנכתבו.

<a id="mezuza-manual-partial"></a>
### איך רושמים מזוזה שהגעתי בה לשורה 16?

בהזנה ידנית בחר מזוזה חדשה, כמות 1 ו„עד שורה” 16. בישיבה הבאה בחר „המשך מזוזה” של אותה מזוזה והזן את השורה המצטברת שאליה הגעת, למשל 22. התוספת תהיה רק שורות 17–22, והמזוזה תיספר כיחידה פיזית אחת.

<a id="mezuza-choose-partial"></a>
### איך בוחרים איזו מזוזה חלקית להמשיך?

בטופס ההזנה בחר את המזוזה לפי מספרה ברשימת ההמשך. אם קיימת מזוזה חלקית אחת היא נבחרת כברירת מחדל. בדוק את ההסבר המציג כמה מתוך 22 שורות כבר נכתבו ומאיזו שורה ממשיכים.

<a id="mezuza-switch"></a>
### אפשר לעבור למזוזה אחרת בלי לסיים את הנוכחית?

כן. במצב חכם אפשר להשתמש ב„עבור למזוזה הבאה” או בבחירת המיקום. המזוזה החלקית נשארת רשומה ואפשר לחזור אליה. מעבר למזוזה אחרת אינו סימון שהמזוזה הקודמת הושלמה.

<a id="mezuza-double"></a>
### שתי ישיבות על אותה מזוזה מוצגות כשתי מזוזות. איך מתקנים?

בדוק אם החלק השני הוזן כ„מזוזה חדשה” במקום כהמשך. במרכז הפרויקט בדוק את שתי היחידות, מחק את הרישום השגוי והזן אותו כהמשך של המזוזה הנכונה. התוכנה אינה מאחדת אוטומטית שתי יחידות בעלות זהות שונה, משום שייתכן שבאמת נכתבו שתי מזוזות.

<a id="mezuza-batch-correction"></a>
### רשמתי כמה מזוזות יחד ואחת נרשמה בטעות. צריך למחוק הכול?

לא. בחלק „הכתיבה” במרכז הפרויקט אפשר לפעול על המזוזה המסוימת. במידת הצורך התוכנה מפרידה אותה מהרישום המשותף ומחלקת את הזמן לפי כמות השורות. בדוק אם נדרשת מחיקת טעות רישום או סימון עבודה שנפסלה — אלו פעולות שונות.

## תפילין

<a id="tefillin-structure"></a>
### איך התוכנה מסדרת הזמנת תפילין?

כל פרשייה מזוהה לפי מספר זוג, של ראש או של יד, ומקומה בארבע הפרשיות. זוג כולל ראש ויד. בלוח התפילין אפשר לראות מה טרם התחיל, מה חלקי, מה הושלם ומה סומן כממתין לתיקון או כפסול.

<a id="tefillin-order"></a>
### למה אי אפשר להתחיל פרשייה מסוימת?

התוכנה שומרת על רצף ארבע הפרשיות באותו סט: קדש, והיה כי יביאך, שמע, והיה אם שמע. הפרשייה הקודמת צריכה להיות שלמה לפני שמתחילים את הבאה. בדוק את הזוג, הצד והפרשייה הקודמת; רישום חלקי או חסר יכול להסביר את החסימה.

<a id="tefillin-physical-lines"></a>
### כמה שורות מזינים בפרשייה של ראש או של יד?

במבנה הנתמך בתוכנה, פרשייה של ראש היא בת 4 שורות ופרשייה של יד בת 7 שורות. אלה השורות הפיזיות לצורך מיקום והמשך. לצורך חישובי זמן והשוואה יש גם מקביל לשורות ספר תורה, שאינו זהה למספר הזה.

<a id="tefillin-continue"></a>
### איך ממשיכים כתיבת תפילין אחרי עצירה?

בחר את הפרשייה מרשימת „המשך כתיבה או כתיבה חדשה”, לפי הזוג והצד. הרשימה מציעה גם פרשייה חלקית וגם את הפרשייה הבאה בסט שהפרשייה הקודמת בו הושלמה. אם יש רק המשך אחד זמין הוא נבחר אוטומטית. הזן עד איזו שורה הגעת עכשיו. למשל, המשך של פרשיית יד משורה 3 לשורה 7 מוסיף את שורות 4–7 בלבד. אחרי סיום „והיה כי יביאך” בזוג 2, אפשר להמשיך ל„שמע” באותו זוג בלי להזין שוב זוג וצד. „הוסף עוד” ממשיך באותו סט; אפשר לבחור במפורש „התחל יחידת תפילין חדשה”. במצב חכם, תחילת הישיבה מתקדמת אוטומטית ממיקום שמור על פרשייה שהושלמה לפרשייה הבאה. פרשייה שנפסלה או שחסרה לה פרשייה קודמת עדיין דורשת תיקון ואינה נעקפת.

<a id="tefillin-switch"></a>
### אפשר לעבור לזוג אחר ולחזור אחר כך?

כן. אפשר לשנות מיקום דרך המיקום הגדול במסך החכם ולבחור זוג וצד אחרים. העבודה החלקית נשמרת. כשחוזרים, בדוק שנבחרה אותה כתובת פיזית ושממשיכים מהשורה הנכונה.

<a id="tefillin-comparable"></a>
### למה מופיעים שני מספרי שורות, למשל 2 (8)?

המספר הראשון הוא השורות הפיזיות בפרשייה. המספר שבסוגריים מציג את המקביל בשורות ספר תורה. למשל, שתי שורות מתוך ארבע בפרשיית קדש של ראש הן חצי מ־16 שורות הבסיס, ולכן מוצגות כ־2 (8). בדוח תפילין ובמרכז הפרויקט הממוצע משתמש בבסיס זה בלי תוספת משקל 1.3; המשקל משמש להשוואה בין סוגי עבודה.

<a id="tefillin-pair-value"></a>
### למה פרשייה אחת אינה תמיד שמינית מהרווח של זוג?

החישוב מתחשב בכמות הטקסט של הפרשייה. בסיס ספר התורה לארבע הפרשיות הוא 16, 12, 7 ו־17 שורות, יחד 52 לראש או ליד ו־104 לזוג. לכן קדש ושמע אינם מקבלים אותו חלק מהספק הזוג או מערכו הכספי.

<a id="tefillin-restart"></a>
### מה עושה „הסר את הפרשייה והתחל מחדש”?

הפעולה מסירה את הפרשייה וגם את הפרשיות שאחריה באותו סט, כדי שאפשר יהיה להתחיל שוב ברצף תקין. היא אינה מוגבלת לפרשייה שעליה לחצת. קרא את אישור הפעולה ובדוק את הזוג והצד לפני אישור. לסימון פסילה בלי מחיקת זמן עבודה השתמש במסלול הפסילה המתאים.

## תיקונים, פסילה וסל המחזור

<a id="correction-delete-invalid"></a>
### מתי מסמנים „העבודה נפסלה” ומתי „מחק רישום שגוי”?

אם העבודה נכתבה בפועל אך נפסלה, סמן פסילה: הזמן שהושקע נשאר, והעבודה אינה נחשבת תוצר תקין או רווח. אם הרשומה עצמה היא טעות, למשל דיווח כפול, בחר מחיקת רישום שגוי: היא יוצאת גם מחישובי הזמן.

<a id="correction-lines"></a>
### איך מוחקים רק שורות מסוימות שנרשמו בטעות?

פתח „מרכז הפרויקט”, „הכתיבה” ואת העמוד הרצוי. בחר את השורות השגויות ובצע את פעולת המחיקה המתאימה. אם הרשומה המקורית כוללת טווח גדול, היא יכולה להתפצל כדי לשמור את שאר העבודה. הזמן של החלקים מחולק ביחס לשורות.

<a id="correction-history"></a>
### איפה מתקנים תאריך או זמן של רשומה?

פתח את תצוגת הרשומות או עורך ההיסטוריה מתוך מסכי הסיכום ומרכז הפרויקט, ובחר את הרשומה לעריכה. בדוק גם את הפרויקט ואת טווח הכתיבה לפני שמירה. מקטע זמן של שורה חלקית אינו רשומת טווח רגילה ולכן אין לערוך אותו כאילו היו בו שורות שהושלמו.

<a id="correction-restore"></a>
### איך משחזרים פרויקט או רשומת כתיבה שנמחקו?

פתח את „סל מחזור” ממסך הפרויקטים ובחר „שחזר” ליד הפריט. הסל מציג פרויקטים, רשומות כתיבה, הזמנות, הגהות, הוצאות ותשלומים שנמחקו ב־30 הימים האחרונים. שחזור פרויקט לבדו אינו משחזר רשומות שנמחקו בנפרד; בדוק גם אותן.

<a id="correction-split-restore"></a>
### האם שחזור רשומה שפוצלה ייצור כפילות?

בתיקון שמפצל רשומה, התוכנה שומרת את הקשר בין המקור לחלקים החדשים. שחזור המקור מסיר את חלקי ההחלפה שנוצרו באותו תיקון, כדי שלא לספור את השורות והזמן פעמיים. לאחר שחזור בדוק את מפת העבודה ואת הסיכום.

<a id="correction-bin-limits"></a>
### איך משחזרים הזמנה או רשומת הגהה שנמחקו?

הסל מציג גם הזמנות, הגהות, הוצאות ותשלומים. פתח אותו ממסך הפרויקטים ובחר „שחזר”. פריט שחלפו יותר מ־30 יום ממחיקתו עשוי להיות מוסתר מהסל. הזמנה שבוטלה נשארת בפנקס ההזמנות; כדי להחזירה בחר „החזר לפעילות”.

<a id="correction-active-project"></a>
### למה מחיקת פרויקט חסומה?

אי אפשר למחוק פרויקט שהטיימר שלו פעיל, כדי שלא לאבד את הישיבה. סיים ושמור את העבודה, ואז חזור למחיקה. אל תשתמש באיפוס כל הנתונים כדי לעקוף את החסימה.

<a id="correction-reset"></a>
### איפה מאפסים את כל הנתונים ומה ההבדל ממחיקה רגילה?

„איפוס כל הנתונים” נמצא בתפריט הפעולות העליון במסך הפרויקטים ודורש אישור מפורש והקלדת מילת אישור. זו פעולה רחבה שאינה מיועדת לתיקון רשומה בודדת. לפני איפוס שמור גיבוי נפרד ובדוק שהוא זמין; אין להסתמך על סל המחזור לשחזור איפוס.

## יומן כתיבה

<a id="journal-open"></a>
### מהו יומן הכתיבה ואיפה פותחים אותו?

פתח „כלים” ואז „יומן כתיבה”. זהו מבט שבועי על הכתיבה מיום ראשון עד שבת, המתאים במיוחד למילוי בדיעבד. במסך רחב מוצגת טבלה, ובמסך צר הרשומות מקובצות לפי ימים.

<a id="journal-add"></a>
### איך מוסיפים עבודה ליום מסוים ביומן?

עבור לשבוע הרצוי ולחץ על „הוסף רשומה” ביום המתאים. נפתח עורך בתוך היומן: בחר פרויקט, מלא טווח עמודים ושורות או כמות, זמן אם ידוע והערות, ולחץ „שמור שורה”. למזוזה חלקית, פרשיית תפילין או בחירת מילים לחץ „טופס מלא”. אפשר ליצור בו את הפרויקט הראשון; היום שנבחר נשמר.

<a id="journal-edit-cells"></a>
### האם אפשר להקליד ישירות בתאי היומן כמו באקסל?

כן. לחץ על שורה קיימת כדי לפתוח את העורך בתוך היומן. אפשר לערוך טווח עמודים, כמות פשוטה, זמן והערות ולשמור. רישומים מורכבים מציעים שינוי זמן והערות לצד „טופס מלא” לעריכת פרטי הכתיבה. הזנה שהתפצלה למקטעים מוצגת בשורה אחת עם סכום זמני הכתיבה. ההערה מופיעה גם ב־PDF וב־Excel.

<a id="journal-home"></a>
### איך הופכים את יומן הכתיבה למסך הבית?

ב„הגדרות” פתח „יומן כתיבה” והפעל את האפשרות להצגתו כמסך הבית. מהיומן אפשר לעבור למסך הטיימר באמצעות הכפתור הייעודי. טיימר פעיל נשאר נגיש ואינו מוסתר על ידי העדפת היומן.

<a id="journal-columns"></a>
### איך משנים את עמודות היומן ואת התאריכים?

ב„הגדרות” ואז „יומן כתיבה” אפשר לבחור עמודות, מספר שורות ריקות ביום ותצוגת תאריך עברי, לועזי או שניהם. הגדרות אלו משמשות את היומן ואת הפלט שלו. בחירת תצוגה אינה משנה את רשומות הכתיבה עצמן.

<a id="journal-parasha"></a>
### למה פרשת השבוע ביומן אינה מתאימה למקום שבו אני גר?

בדוק בהגדרות היומן אם נבחר לוח ארץ ישראל או לוח חו״ל. בתקופות מסוימות הקריאה שונה בין הלוחות. זו בחירה מפורשת בהגדרות היומן; אל תניח ששינוי הגדרת מקום במסך אחר שינה גם אותה.

<a id="journal-print"></a>
### איך מדפיסים דף שבועי או מייצאים לאקסל?

בחר את השבוע והשתמש בפעולת הדפסת טבלה ריקה, הדפסת שבוע מלא או ייצוא ל־Excel. טבלה ריקה מיועדת למילוי ידני. קובץ Excel הוא פלט לעיון ולעיבוד; אין בממשק הנוכחי מסלול כללי לייבוא טבלה שערכה תוכנה חיצונית בחזרה ליומן.

## הזמנות ולקוחות

<a id="orders-vs-project"></a>
### מה ההבדל בין הזמנה לפרויקט?

פרויקט מתעד את הכתיבה והחישובים של עבודה מסוימת. הזמנה מתעדת התחייבות ללקוח ויכולה לכלול כמה סוגי עבודות יחד, למשל מזוזות ומגילה. אפשר לקשר פריט בהזמנה לפרויקט קיים, אך הקישור אינו יוצר מעצמו כתיבה, תשלום או אספקה.

<a id="orders-create"></a>
### איך רושמים הזמנה חדשה?

פתח „כלים” ואז „הזמנות”. הוסף הזמנה ומלא פרטי מזמין, תאריך, מועד מסירה ופריטים. לכל פריט אפשר לקבוע סוג עבודה, כמות והערות; להזמנה אפשר להוסיף דרישות, מחיר כולל ומטבע.

<a id="orders-partial"></a>
### איך מסמנים אספקה חלקית?

ערוך את ההזמנה ועדכן בכל פריט כמה יחידות סופקו. כך אפשר לעקוב אחרי הזמנה שחלקה כבר נמסר וחלקה עדיין פתוח. סימון „סופקה” מתאים רק כאשר ההזמנה נמסרה בהתאם לפרטיה; השלמת כתיבה בפרויקט אינה תחליף לרישום האספקה.

<a id="orders-search"></a>
### איך מוצאים הזמנות לחודש מסוים?

במסך ההזמנות השתמש בחיפוש ובסינון לפי חודש המסירה. בדוק את מועד המסירה שנשמר בהזמנה אם היא אינה מופיעה בחודש שציפית. פנקס ההזמנות מיועד גם לבדיקה יזומה של ההתחייבויות הקרובות. הזמנה מבוטלת נשארת גלויה, אך אינה נספרת כפתוחה או באיחור. בתפריט ההזמנה אפשר לבחור „בטל הזמנה” או „החזר לפעילות”; פרטים וכמויות שסופקו נשמרים.

<a id="orders-reminders"></a>
### האם הזמנה שולחת תזכורת אוטומטית לפני המסירה?

לא. פנקס ההזמנות הנוכחי אינו מפעיל התראות אוטומטיות על מועדי מסירה. התזכורות היומיות לכתיבה הן אפשרות נפרדת ואינן תזכורות להזמנות.

<a id="client-update"></a>
### איך מכינים עדכון התקדמות ללקוח?

במרכז הפרויקט בחר „שלח עדכון ללקוח”. אפשר לעיין בנוסח, להעתיק אותו או לפתוח אותו בתוכנת הדואר. הגדר את „שם הסופר” בהגדרות כדי שיופיע בחתימה, והוסף אימייל לקוח לפרויקט אם רוצים לפתוח דואר אליו. התוכנה אינה שולחת את ההודעה בעצמה.

## יעדים, קצב ותכנון

<a id="goals-set"></a>
### איך מגדירים יעד יומי וחודשי?

ערוך את פרטי הפרויקט ומלא את שדות היעדים. בספר תורה ובמגילה אפשר לבחור יעד יומי בעמודים או בשורות; במזוזות היחידה היא מזוזות ובתפילין פרשיות ליום. בדוק את היחידה בטופס. יעד כמות כתיבה שונה מיעד זמן לישיבה.

<a id="goals-no-target"></a>
### האם חייבים להגדיר יעד כדי לעבוד?

לא. אפשר לתעד כתיבה ולצפות בסיכומים גם בלי יעד. אפשרויות כמו לוח הספקים ועמידה ביעד זקוקות ליעד מתאים. אם הלוח אומר שאין מה לתכנן, פתח את פרטי הפרויקט והגדר יעד יומי.

<a id="goals-estimate"></a>
### איך נקבע צפי הסיום?

הצפי תלוי ביתרת העבודה, בקצב הזמין לחישוב או ביעד שהוגדר ובימי העבודה. דרוש גם היקף כולל, כגון מספר עמודים או כמות מזוזות או זוגות בהזמנה. כשחסרים היקף או קצב, לא ניתן להפיק תחזית שימושית.

<a id="goals-deadline"></a>
### שיניתי תאריך יעד. למה צפי הסיום לא השתנה?

תאריך היעד הוא המועד שבו אתה רוצה לסיים; צפי הסיום מתאר מתי תסיים לפי הקצב. שינוי תאריך אינו משנה את קצב הכתיבה שנמדד. השדה שצריך להתעדכן הוא „נדרש כדי לעמוד בתאריך היעד”. תאריכים שונים הכוללים אותו מספר ימי עבודה יכולים להציג אותה דרישה ליום.

<a id="goals-plan"></a>
### מה מציג לוח ההספקים?

פתח „כלים” ואז „לוח הספקים”, בחר פרויקט ותצוגת שבוע או חודש. כל יום מראה לאיזה מקום צריך להגיע עד סופו, ולא רק כמה לכתוב באותו יום. הלוח מתחשב בימי העבודה ומאפשר גם הדפסה, שמירה כ־PDF וייצוא ל־Excel.

<a id="goals-behind"></a>
### מה קורה בתכנון אם פיגרתי או איני עובד ביום מסוים?

הפיגור מתחלק על ימי העבודה שנותרו, בעוד שיעדי ימים שכבר עברו נשארים לצורך השוואה. בלוח אפשר לבחור יום ולסמן יום מלא, חצי יום או „לא כותב”, ולחזור להגדרת הלוח הכללית. שינוי זה שייך לפרויקט שנבחר ומשפיע גם על צפי הסיום ועל הקצב הנדרש לתאריך היעד שלו.

לאירוע אישי בכל הפרויקטים, פתח „הגדרות” ← „ימי עבודה” ← „הוסף תאריך חריג”. יום חופש או חצי יום אישי מגביל גם שינוי יום בתוך פרויקט. שינוי תוכנית אינו מוסיף רשומות כאילו העבודה כבר נעשתה.

<a id="goals-pace"></a>
### למה אין עדיין ממוצע או מידע על שעות הכתיבה הטובות שלי?

ממוצע זקוק לרשומות עם זמן כתיבה תקין. ניתוח שעות זקוק גם לשעת התחלה אמיתית; משך כולל ללא שעה אינו מלמד מתי כתבת. ככל שמצטבר תיעוד מתאים, אפשר לחשב קצב ולהציג דפוסים. השלמת עבר ללא תאריך אינה בסיס למדידה כזו.

<a id="goals-minute-format"></a>
### האם 1.50 דקות לשורה פירושן דקה וחמישים שניות?

לא. זהו מספר עשרוני של דקות: 1.50 דקות הן דקה וחצי, כלומר דקה ו־30 שניות. תצוגת שעון כמו 1:30 משתמשת בנקודתיים ומציגה דקות ושניות. החישוב כולל את השניות שנמדדו גם כשהתוצאה מוצגת בדקות עשרוניות.

## תאריכים וימי עבודה

<a id="calendar-display"></a>
### איך מחליפים בין תאריך עברי ללועזי?

בהגדרות אפשר לשנות את תצוגת התאריכים באמצעות „תאריכים לועזיים”. חישובי חגים וימי עבודה ממשיכים להשתמש בלוח העברי. ליומן הכתיבה יש בחירת תאריך נפרדת, והדוח השנתי משתמש בשנה לועזית.

<a id="calendar-day-boundary"></a>
### מהי הגדרת „מעבר יום”?

ההגדרה קובעת מתי מתחיל יום עבודה חדש לצורכי שיוך רשומות וסיכומים. אפשר לבחור חצות, שקיעה, צאת הכוכבים או שעה קבועה. לדוגמה, שעה קבועה מאוחרת מחצות יכולה לאפשר לכתיבה אחרי חצות להישאר ביום העבודה הקודם.

<a id="calendar-history"></a>
### האם שינוי „מעבר יום” יעביר גם רשומות ישנות ליום אחר?

ברשומות החדשות יום העבודה נקבע ונשמר בעת הרישום, ולכן שינוי ההגדרה אינו אמור לשייך אותן מחדש. רשומות ותיקות שאין בהן יום עבודה שמור עשויות להשתמש בחישוב התאימות. אם יש ספק, בדוק את הרשומה עצמה לפני שינוי תאריכים ידני.

<a id="calendar-sunset"></a>
### האם השקיעה וצאת הכוכבים מחושבים לפי המיקום שלי?

התוכנה משתמשת בנקודת ייחוס של ארץ ישראל ולא ב־GPS של המכשיר. זהו חישוב לצורכי מעבר יום ועיצוב, ולא לוח זמנים אישי למקום מגוריך. אם החישוב אינו מתאים לשגרת העבודה שלך, אפשר לבחור שעה קבועה למעבר יום.

<a id="calendar-workdays"></a>
### איך קובעים באילו ימים כותבים?

פתח „הגדרות” ואז „ימי עבודה”. בקטגוריות הניתנות לשינוי אפשר לבחור יום מלא, חצי יום או לא לעבוד, למשל ביום שישי, במוצאי שבת ובמועדים המופיעים במסך.

לחתונה, שבע ברכות או אירוע אחר, ב„חריגות אישיות לפי תאריך” לחץ „הוסף תאריך חריג”. בחר תאריך עברי או לועזי ושנה, יום חופש או חצי יום, והוסף הערה אם תרצה. לדוגמה, אפשר לסמן ט״ו בשבט של השנה הרצויה כיום חופש ואת ימי שבע הברכות כחצאי ימים. אפשר לערוך חריגה בלחיצה עליה או למחוק באמצעות הפח.

החריגות חלות על כל הפרויקטים ונכללות בלוח ההספקים, בצפי הסיום, בקצב הנדרש ליעד, ביעדים חודשיים ובהצעות מחיר. הן נשמרות בגיבוי, אינן חוזרות בשנה הבאה ואינן משנות כתיבה שכבר נשמרה או את הקצב שנמדד. חצי יום אינו פותח יום שכבר סגור בלוח. תצוגת החודש הקרוב עוזרת לבדוק את התוצאה לפני שמסתמכים על התחזית.

<a id="calendar-fixed-days"></a>
### למה חלק מהימים אינם ניתנים להפעלה כימי עבודה רגילים?

התוכנה מחריגה באופן קבוע שבת, יום טוב, חול המועד, ערבי חג, פורים ושושן פורים, תשעה באב וערב תשעה באב. החרגות אלו גוברות על קטגוריות אחרות בתכנון. זו התנהגות לוח העבודה של התוכנה; השאלה כאן עוסקת בתכנון ולא בפסק הלכה.

<a id="calendar-diaspora"></a>
### אני בחו״ל. מה צריך לשנות?

ב„ימי עבודה” בדוק את הבחירה „בארץ ישראל”, המשפיעה על ימי החג בתכנון. ביומן הכתיבה בחר בנפרד לוח פרשיות חו״ל. בדוק גם שמועד מעבר היום מתאים לך, משום שחישוב השקיעה אינו מבוסס על מיקומך האישי.

## רווח, הוצאות, תשלומים ומטבע

<a id="money-profit-vs-payment"></a>
### האם „רווח” אומר שהלקוח כבר שילם?

לא. הרווח מחושב מהעבודה שנרשמה ומהמחיר וההוצאות שהוגדרו. כסף שהתקבל בפועל נרשם בנפרד ב„תשלומים”. לכן ייתכן שנצבר רווח לפי הכתיבה אך עדיין לא התקבל תשלום, או שהתקבלה מקדמה לפני הכתיבה.

<a id="money-base-profit"></a>
### איך מחושב הרווח מהכתיבה?

חישוב הבסיס הוא כמות העבודה המזכה כפול המחיר ליחידה, בניכוי הוצאות הבסיס ליחידה. בחלק ממסכי הסיכום מוצגות בנפרד הוצאות משויכות ויתרת נטו לאחר הוצאות נוספות. בדוק את כותרת הנתון: „רווח”, „הוצאות משויכות” ו„נטו” אינם תמיד אותו סכום.

<a id="money-hourly"></a>
### איך מחושב השכר לשעה?

השכר לשעה מחלק את הרווח המתאים לרשומות המדודות בזמן העבודה שלהן. רשומה בלי זמן אינה נחשבת כתיבה של אפס דקות. זמן שהושקע בעבודה שנפסלה נשאר זמן אמיתי בלי להוסיף רווח. הנתון הוא מדד מתוך התיעוד שלך, ולא תשלום שהתקבל מהלקוח.

<a id="money-expense-add"></a>
### איך רושמים הוצאה?

פתח את מסך „הוצאות” והוסף הוצאה עם מוצר או קטגוריה, תאריך וסכום. בחר אם לשייך אותה לפרויקט, לתקופה או לחודש. אפשר לערוך הוצאה קיימת אם התברר שהסכום או השיוך שגויים.

<a id="money-expense-allocation"></a>
### מה ההבדל בין הוצאה לפי פרויקט, תקופה וחודש?

הוצאה לפי פרויקט משויכת לעבודות שבחרת; בבחירת כמה פרויקטים הסכום מתחלק ביניהם. הוצאה לפי תקופה נפרסת על פני הימים בין שני תאריכים. הוצאה לפי חודש נזקפת לחודש שבו בוצעה. הוצאה המסומנת לפי פרויקט בלי בחירת פרויקט אינה נכללת בחישוב של עבודה מסוימת.

<a id="money-double-expense"></a>
### כבר כתבתי הוצאות בפרויקט. האם לרשום שוב את אותה קנייה?

הוצאות הבסיס בטופס הפרויקט משמשות לאומדן הרווח ליחידה, ואילו מסך ההוצאות מתעד הוצאות מפורטות. בדוק שלא ניכית את אותה עלות פעמיים בחישוב שבו אתה משתמש. הדוח השנתי אינו מוסיף את אומדן הוצאות היחידה כהוצאה בפועל; הוא משתמש ברישומי ההוצאות ובעלויות ההגהה המתאימות.

<a id="money-payment-record"></a>
### איך רושמים מקדמה או תשלום מהלקוח?

פתח את אזור התשלומים במרכז הפרויקט ובחר „רישום תשלום”. מלא סכום, מועד קבלה ואפשר להוסיף אופן תשלום והערות. אפשר לרשום כמה תשלומים לאותו פרויקט. הרישום מתעד כסף שקיבלת; הוא אינו גובה כסף ואינו שולח דרישת תשלום.

<a id="money-outstanding"></a>
### מה פירוש „נותר לתשלום” ו„שולם מראש”?

היתרה משווה את התשלומים שנרשמו לשווי העבודה שכבר נכתבה, ולא בהכרח למחיר כל ההזמנה העתידית. אם התקבל יותר משווי הכתיבה עד כה, ההפרש מוצג כתשלום מראש. אם יש תשלומים במטבעות שאי אפשר לחבר, לא תוצג יתרה מספרית יחידה.

<a id="money-currency"></a>
### איך מחליפים מטבע? האם הסכומים הקיימים יומרו?

ב„הגדרות” ואז „מטבע” אפשר לבחור שקל, דולר, אירו או לירה שטרלינג. הבחירה קובעת את המטבע לסכומים חדשים. סכומים קיימים שומרים את המטבע שבו נרשמו; התוכנה אינה ממירה שערים ואינה מחברת סכומים במטבעות שונים לסכום יחיד.

<a id="money-zero-profit"></a>
### למה ההספק גדל אבל הרווח לא גדל?

בדוק שהמחיר בפרויקט אינו 0, שהרשומה אינה „ללא תאריך” כהשלמת עבר, ושהעבודה לא סומנה כפסולה. מקטע זמן של שורה חלקית מוסיף זמן אך לא תוצר או רווח עד השלמת השורה. בדוק גם אם הוצאות הבסיס שוות למחיר או גבוהות ממנו.

## מעקב הגהה

<a id="proofread-add"></a>
### איך רושמים עבודה שנשלחה למגיה?

פתח „כלים” ואז „מעקב הגהה” והוסף רשומה. בחר פרויקט ומלא מה נשלח, מי המגיה, שלב, תאריך ועלות אם ידועה. אפשר לכתוב תיאור כמו טווח עמודים או כמות מזוזות, ולהוסיף הערות ומספר תיקונים שנמצאו.

<a id="proofread-stages"></a>
### איך מעדכנים שהעבודה חזרה ושהתיקונים הושלמו?

במעקב ההגהה ניתן לעדכן את שלבי העבודה, למשל „נשלח למגיה”, „חזר מהמגיה” ו„התיקונים הושלמו”. ודא שגם התאריכים נכונים. הסיכום מבחין בין עבודה שעדיין אצל המגיה לבין עבודה שממתינה לטיפול שלך.

<a id="proofread-cost"></a>
### איך עלות ההגהה נכנסת לדוחות?

עלות שנרשמה במעקב ההגהה משויכת לפרויקט ומופיעה בחישובים הרלוונטיים. בדוח השנתי היא משויכת לפי תאריך השלמת התיקונים אם קיים, ואחרת לפי תאריך החזרה. אין כאן שדה נפרד למועד תשלום ההגהה; בדוק את התאמת הנתונים כשמפיקים דוח.

<a id="proofread-long-time"></a>
### למה מוצג שהעבודה אצל המגיה זמן רב?

המסך משווה את מועד השליחה למצב הרשומה. עבודה שיצאה לפני יותר משלושה שבועות ולא סומנה כחוזרת יכולה להופיע בחיווי המתאים. אם כבר חזרה, עדכן את השלב ואת תאריך החזרה.

<a id="proofread-not-validation"></a>
### האם סימון „הכול הושלם” מאשר שהכתיבה כשרה?

לא. הסימון מתאר את מצב הטיפול כפי שנרשם בתוכנה. היא אינה קוראת את הכתב, אינה מבצעת הגהה ואינה נותנת אישור כשרות. המעקב נועד לרישום העבודה והבדיקות שנעשו מחוץ לתוכנה.

## הצעת מחיר והשוואת רווחיות

<a id="quote-open"></a>
### איך משתמשים במחשבון הצעת מחיר?

פתח „כלים” ואז „מחשבון הצעת מחיר”. בחר סוג עבודה וכמות, ובמגילה גם מבנה. מלא את נתוני העבודה וההוצאות המבוקשים במסך ובדוק את הקצב, הזמן, המחיר וצפי הסיום המחושבים. התוצאה תלויה בנתונים שהזנת ובהיסטוריה הזמינה.

<a id="quote-no-history"></a>
### אין לי עדיין היסטוריה מהסוג הזה. איך המחשבון מעריך זמן?

המחשבון מעדיף נתוני זמן מאותו סוג עבודה. אם אין נתון מתאים, הוא יכול להסתמך על סוג עבודה אחר לפי סדר הקדימות המוגדר, תוך שימוש ביחידות השוואה. בדוק מהו בסיס ההערכה; קצב שנלמד מסוג אחר הוא אומדן, וכדאי לעדכן את ההערכה לאחר שנצבר ניסיון באותו סוג.

<a id="quote-weights"></a>
### מהם משקלי ההשוואה בין סוגי הכתיבה?

בציר ההשוואה שורת ספר תורה ומגילה מקבלות משקל 1, שורת מזוזה 1.1 ותפילין 1.3 על בסיס המקביל לשורות ספר תורה. זוג תפילין הוא 104 שורות בסיס, או 135.2 לאחר המשקל. אלו כללי החישוב של התוכנה; הם אינם משנים את מספר השורות הפיזיות שנרשמו.

<a id="quote-overhead"></a>
### האם ההצעה כוללת את כל ההוצאות הכלליות שלי?

לא באופן אוטומטי. המסך מציג הוצאות כלליות ומאפשר לערוך אותן, ומתג מפורש מאפשר לפרוס אותן על ההצעה במטבע המתאים. הוצאות שמזינים להצעה עצמה נשארות נפרדות. בדוק אם הסכום הוא ליחידה או לכל העבודה ומה כלול לפני שאתה משתמש במחיר.

<a id="quote-create-project"></a>
### אפשר להפוך הצעת מחיר לפרויקט?

כן. בחר „צור פרויקט מההצעה” ותן שם לפרויקט. המחיר וההוצאות נשמרים ביחידה המתאימה לסוג העבודה. הפרויקט הוא פרויקט רגיל וניתן לעריכה בהמשך; יצירתו אינה שולחת את ההצעה ללקוח.

<a id="quote-compare"></a>
### מה לומדים מ„השוואת רווחיות”?

המסך משווה פרויקטים לפי הרווח ביחס לזמן שנמדד. מחיר גבוה ליחידה אינו בהכרח שכר גבוה לשעה אם כתיבתה איטית. בדוק כמה נתונים מדודים יש לכל פרויקט ואיזה מטבע מוצג. אין לפרש סכומים במטבעות שונים כאילו הומרו לאותו מטבע.

## סיכומים ודוחות

<a id="reports-types"></a>
### מה ההבדל בין סיכום יומי, סיכום חודשי ומרכז פרויקט?

הסיכום היומי מרכז את יום העבודה שנבחר, הסיכום החודשי מרכז את החודש, ומרכז הפרויקט מציג את אותה עבודה לאורך חיי הפרויקט. מסנני פרויקט ותקופה משפיעים על מה שנכלל. כדי להשוות שני מספרים, ודא ששניהם מתייחסים לאותה תקופה ולאותו פרויקט.

<a id="reports-monthly"></a>
### מה כולל הדוח החודשי המפורט?

פתח „כלים” ואז „דוח חודשי”. בחר חודש ופרויקט או את כל הפרויקטים. הדוח מציג יום אחר יום כמות כתיבה, זמן, ממוצע ורווח; ימים בלי כתיבה נשארים ריקים. ניתן להדפיס או לשמור כ־PDF ולייצא ל־Excel.

<a id="reports-annual"></a>
### למה הדוח השנתי הוא מינואר עד דצמבר?

הדוח השנתי מאורגן לפי שנה לועזית, בשונה מחלקי התוכנה שמרכזים עבודה בחודשים עבריים. בחר את השנה הרצויה ובדוק את פירוט החודשים. שינוי תצוגת תאריכים בהגדרות אינו הופך את הדוח השנתי לשנה עברית.

<a id="reports-annual-income"></a>
### למה הכנסות הדוח השנתי שונות משווי הכתיבה השנה?

הכנסות בדוח השנתי הן תשלומים שנרשמו לפי מועד קבלתם. עבודה שנכתבה אך טרם שולמה אינה תשלום, ותשלום שהתקבל השנה יכול להיות עבור עבודה משנה קודמת. כדי שהדוח ישקף כסף שהתקבל, צריך לרשום תשלומים ולא רק כתיבה.

<a id="reports-invalid-time"></a>
### למה נשאר זמן בדוח אחרי שפסלתי עבודה?

הפסילה מוציאה את העבודה מהתוצר התקין ומהרווח, אך הזמן שהושקע בה נשאר. הוא יכול להשפיע על קצב ושכר לשעה ומוצג בנפרד במקום המתאים. אם לא הייתה עבודה כלל אלא טעות רישום, מחיקת הרשומה היא הפעולה המתאימה.

<a id="reports-export-backup"></a>
### האם PDF או Excel הם גיבוי של התוכנה?

לא. אלו דוחות של הנתונים שנבחרו להצגה, ואינם כוללים בהכרח את כל הפרויקטים, ההגדרות והמידע לשחזור. להעברה למכשיר אחר או להגנה על הנתונים השתמש ב„גיבוי הנתונים” ושמור את קובץ הגיבוי.

<a id="reports-language"></a>
### באיזו שפה נוצרים הדוחות והעדכון ללקוח?

הם נוצרים לפי שפת הממשק שנבחרה. בממשק אנגלי הפלט המיועד לכך מוצג משמאל לימין. שמות פרויקטים, הערות ונתונים שהזנת אינם מתורגמים מחדש; מספרי עמודי ספר תורה ושמות פרשיות תפילין יכולים להישאר בעברית.

## גיבוי, שחזור והעברה בין מכשירים

<a id="backup-local"></a>
### איפה נשמרים הנתונים שלי?

הנתונים הפעילים נשמרים מקומית במכשיר. אין חשבון ענן של התוכנה שאליו אפשר להתחבר ולקבל אותם מחדש. כדי להגן עליהם מפני אובדן מכשיר או מחיקת נתוני האפליקציה צריך לשמור גם גיבוי חיצוני.

<a id="backup-manual"></a>
### איך יוצרים גיבוי ידני?

פתח „הגדרות”, „גיבוי הנתונים” ובחר „שמור במכשיר”. בחר מקום לקובץ ובדוק שהשמירה הצליחה ושהקובץ נמצא שם. אפשר גם להשתמש ב„שיתוף” להעברת הקובץ דרך אפליקציה אחרת. כדאי להחזיק עותק נוסף מחוץ למכשיר שעליו עובדים.

<a id="backup-contents"></a>
### מה נכלל בקובץ הגיבוי?

הגיבוי כולל פרויקטים, היסטוריית עבודה, הוצאות, הגהות, תשלומים, הזמנות ומידע לשחזור סביבת העבודה. הגדרות משתמש ניידות כגון שפה, עיצוב, נגישות וכללי עבודה נכללות ומשוחזרות בגרסה הנוכחית. קובץ הגיבוי הוא קובץ נתונים, ולא דוח PDF או Excel.

<a id="backup-exclusions"></a>
### מה אינו עובר עם הגיבוי למכשיר אחר?

טיימר פעיל וטיוטת טופס שלא הושלמה אינם עוברים כישיבה פעילה במכשיר השני. גם נתיבי תיקיות, הרשאות מערכת וגודל חלון הם פרטי מכשיר. סיים ושמור את הישיבה לפני מעבר, ובמכשיר החדש בחר שוב תיקיית גיבוי ואשר הרשאות נחוצות.

<a id="backup-live-enable"></a>
### איך מפעילים גיבוי אוטומטי חי?

בהגדרות בחר „גיבוי אוטומטי” ובחר תיקייה. ב־Android מאשרים גישה דרך בוחר התיקיות של המערכת; ב־Windows בוחרים תיקייה רגילה. המנגנון נועד לעדכן את הקובץ אחרי שמירות נתונים והגדרות. לאחר ההפעלה בדוק בפועל שהקובץ נוצר ומתעדכן — הכיתוב „פעיל” לבדו אינו בדיקת שחזור.

<a id="backup-live-file"></a>
### למה יש רק קובץ גיבוי אוטומטי אחד?

הגיבוי החי משתמש בקובץ „sofer-vmone-live.json” שמוחלף בעותק עדכני. הוא אינו ארכיון של גרסאות יומיות. כדי לשמור נקודה קודמת שאפשר לחזור ולבדוק, צור מדי פעם גיבוי ידני נפרד, במיוחד לפני שינוי רחב או עדכון.

<a id="backup-live-failure"></a>
### הגיבוי האוטומטי פעיל אבל הקובץ לא מתעדכן. מה עושים?

בהגדרות „גיבוי אוטומטי” מוצגים מועד ההצלחה האחרון ושגיאות, כולל כשלים רצופים. בדוק שהתיקייה קיימת ונגישה ושיש מקום פנוי. ב־Android בחר אותה מחדש לאחר חידוש הרשאה; ב־Windows בדוק שהכונן מחובר. צור גם גיבוי ידני למיקום זמין. כשל בגיבוי החיצוני אינו אומר שהשמירה המקומית נכשלה; אחסון פגום חוסם ייצוא ואינו מחליף את הקובץ הקודם בגיבוי ריק.

<a id="backup-disable"></a>
### איך מכבים גיבוי אוטומטי?

בחר שוב „גיבוי אוטומטי” בהגדרות ואשר את הכיבוי. העדכונים הבאים לקובץ ייפסקו. קבצים שכבר נשמרו בתיקייה נשארים בה ואינם נמחקים מעצם הכיבוי.

<a id="backup-restore"></a>
### איך משחזרים גיבוי?

פתח „הגדרות”, „גיבוי הנתונים” ואז „שחזור מקובץ גיבוי”. בחר קובץ, עיין בפרטי התצוגה המקדימה ובאזהרות אם מופיעות, ואשר שחזור. לאחר מכן בדוק פרויקטים, היסטוריה, כספים והגדרות. שמור את קובץ המקור גם אחרי הייבוא.

<a id="backup-merge"></a>
### האם שחזור גיבוי מחליף את כל הנתונים במכשיר?

השחזור ממזג לפי מזהי הרשומות: פריט אינו נמחק רק משום שאינו נמצא בקובץ המיובא. אם אותה רשומה קיימת בשני הצדדים, התוכן שנערך מאוחר יותר קובע, ומידע על מחיקה ושחזור נשמר גם הוא. הגדרות ניידות עשויות להשתנות לפי הגיבוי. זה אינו כפתור להחזרת כל המכשיר לנקודת זמן קודמת.

<a id="backup-old-delete"></a>
### למה ייבוא גיבוי ישן לא החזיר רשומה שמחקתי?

המיזוג שומר גם את עובדת המחיקה, כדי שקובץ ישן לא יחזיר שוב ושוב פריטים שהסרת. לשחזור פרויקט או רשומת כתיבה שנמחקו לאחרונה השתמש בסל המחזור. במקרה אחר שמור את הגיבוי הישן ופנה לבירור לפני איפוס או הזנה מחדש.

<a id="backup-repeat-import"></a>
### אם אייבא את אותו קובץ פעמיים, הכול יוכפל?

ייבוא חוזר של אותן רשומות בעלות אותם מזהים אינו אמור ליצור עותקים נוספים. עם זאת, עבודה שהוקלדה בנפרד בשני מכשירים יכולה לקבל מזהים שונים ולהיחשב שתי רשומות, גם אם היא מתארת אותה כתיבה. הימנע מתיעוד כפול של אותה עבודה.

<a id="backup-transfer"></a>
### איך מעבירים את העבודה מטלפון למחשב או למכשיר חדש?

סיים ושמור את הישיבה במכשיר המקור, צור גיבוי והעבר את הקובץ למכשיר היעד. פתח שם גרסה תואמת או חדשה יותר וייבא את הגיבוי. בדוק את הנתונים לפני המשך עבודה, ואז הגדר במכשיר החדש הרשאות ותיקיית גיבוי משלו.

<a id="backup-sync"></a>
### האם גיבוי בתיקיית ענן מסנכרן אוטומטית שני מכשירים?

לא. שירות הענן יכול להעביר את הקובץ, אבל התוכנה אינה קוראת וממזגת אותו אוטומטית בכל מכשיר. הגיבוי החי הוא ייצוא של מצב המכשיר. השתמש בתיקייה נפרדת לכל מכשיר כדי שלא יחליפו זה את קובצו של זה, ובצע ייבוא יזום לפני מעבר עבודה.

<a id="backup-legacy"></a>
### יש לי נתונים מגרסה ישנה שאין בה מסך גיבוי. מה עושים?

במסך „גיבוי הנתונים” קיימת „ייבוא מהתקנה קודמת”. האפשרות מיועדת לקובצי נתונים ישנים שניתן להשיג מן ההתקנה הקודמת. אל תסיר את ההתקנה הישנה או תמחק את נתוניה לפני שקיים קובץ שניתן לקרוא ולייבא.

<a id="backup-private"></a>
### האם קובץ הגיבוי מוצפן או מוגן בסיסמה?

הגיבוי הוא קובץ JSON קריא, ואינו גיבוי מוצפן בסיסמה מטעם התוכנה. הוא עשוי לכלול שמות, פרטי לקוחות וסכומים. שמור אותו במקום מתאים ושתף אותו רק עם מי שהתכוונת לתת לו גישה למידע. בדיקת שלמות הקובץ אינה הצפנה.

## התאמה אישית, צלילים ונגישות

<a id="settings-theme"></a>
### איך משנים את מראה התוכנה?

פתח „הגדרות” ואז „עיצוב” ובחר מודרני, קלף או לילה. הפעולות והנתונים משותפים לערכות, גם כשהפריסה שונה. ניתן להפעיל מעבר אוטומטי ללילה מצאת הכוכבים עד עלות השחר לפי חישוב התוכנה.

<a id="settings-text-size"></a>
### הכיתוב קטן לי. איך מגדילים אותו?

פתח „הגדרות” ואז „נגישות” ובחר 100%, 125%, 160% או 200%. השינוי חל מיד. אם הגדלת הכתב במכשיר גבוהה יותר, היא מקבלת עדיפות; שתי ההגדלות אינן מוכפלות. במסך צפוף ייתכן שתצטרך לגלול כדי להגיע לכל הפעולות.

<a id="settings-language"></a>
### איך עוברים לאנגלית? האם הנתונים יתורגמו?

בחר את השפה בהגדרות. השינוי חל על הממשק וכיוון התצוגה, ואינו משכתב שמות פרויקטים, הערות או רשומות שכבר נשמרו. בהתקנה חדשה בוחרים שפה בפתיחה; התקנה ותיקה אינה עוברת לאנגלית רק בגלל עדכון.

<a id="settings-additions"></a>
### למה איני רואה מטרונום, יעד זמן או חגיגה בהגעה ליעד?

התוספות כבויות כברירת מחדל. פתח „הגדרות” ואז „תוספות למסך הבית” והפעל רק את האפשרויות הרצויות. ההגדרות כוללות, בין היתר, חגיגה ביעד יומי, יעד זמן לשורה, מטרונום, יעד לישיבה ושעת סיום.

<a id="settings-line-target"></a>
### מה אומר יעד שורה אדום או מספר שלילי?

יעד זמן לשורה משווה את הזמן שהושקע בשורה למשך שבחרת. אחרי חריגה הוא מציג אדום וזמן במינוס, כדי להראות בכמה עברת את היעד. זה אינו זמן עבודה שלילי ואינו מוחק זמן שנמדד.

<a id="settings-session-target"></a>
### איך קובעים יעד של 45 דקות כתיבה?

הפעל את הצגת יעד הישיבה בתוספות למסך הבית, ואז בחר את משך היעד במסך הבית עצמו. אפשר לבחור 30, 45, 60 או 90 דקות, זמן אחר או להסיר יעד. היעד מודד כתיבה נטו בלי הפסקות ומתאפס בסיום הישיבה; הבחירה האחרונה היא הצעה לישיבה הבאה.

<a id="settings-target-sound"></a>
### הגעתי ליעד הישיבה ולא שמעתי צליל. למה?

„צליל בהגעה ליעד הישיבה” הוא מתג נפרד, כבוי כברירת מחדל. הפעל אותו ובדוק את הצליל בכפתור הבדיקה. ההגעה ליעד מציינת שהושלם משך הכתיבה שבחרת; היא אינה מסיימת ושומרת את הישיבה במקומך.

<a id="settings-metronome"></a>
### איך מפעילים מטרונום ומשנים את העוצמה?

בתוספות למסך הבית הפעל מטרונום, כוון את הקצב והעוצמה והשתמש בכפתור הבדיקה. העוצמה ניתנת להגדרה בין 0 ל־100; ב־0 לא תישמע פעימה. המטרונום פועל בזמן כתיבה ונעצר בהפסקה. הצליל אינו דורש אינטרנט.

<a id="settings-end-time"></a>
### מה ההבדל בין שעת סיום לבין יעד לישיבה?

שעת סיום היא שעה בשעון, למשל 22:00. יעד ישיבה הוא כמות זמן כתיבה נטו, למשל 45 דקות, ולכן הפסקות דוחות את ההגעה אליו. ב־Android התראת שעת הסיום יכולה להיעזר בהתראות המערכת; ב־Windows ההתראה היא בתוך התוכנה.

<a id="settings-reminder"></a>
### איך מפעילים תזכורת יומית או תזכורת לפי ההרגלים?

באפשרויות התזכורות בהגדרות אפשר להפעיל התראה יומית ולבחור שעה. האפשרות „תזכורת לפי ההרגלים שלי” משתמשת בנתוני שעות התחלת כתיבה כשנצבר דפוס מתאים. בלי מספיק נתונים מתאימים, אל תצפה שהמערכת כבר תכיר את שעת העבודה שלך.

## שימוש במחשב וקיצורי מקלדת

<a id="desktop-shortcuts"></a>
### מהם קיצורי המקלדת הרגילים?

בגרסת המחשב ברירת המחדל היא F2 להתחלה ולסיום ישיבה, F3 להפסקה ולהמשך, ו־F4 לפעולת השורה. במצב חכם פעולת השורה רושמת השלמת שורה; במצב רגיל היא מאפסת את זמן השורה בלבד. בחלק מהמקלדות צריך להחזיק גם Fn כדי להפעיל מקש F.

<a id="desktop-custom-shortcuts"></a>
### איך משנים קיצור מקלדת?

פתח „הגדרות” ואז „קיצורי מקלדת” והקצה את המקשים לפעולות. אפשר להשתמש בצירופים עם Ctrl, Shift או Alt. אות או ספרה לבדן אינן קיצור מתאים, כדי שלא יופעל טיימר בזמן הקלדה. השתמש בצירוף נפרד לכל פעולה.

<a id="desktop-shortcut-focus"></a>
### למה קיצור אינו מגיב כשאני מקליד בטופס?

הקיצורים מוגבלים כדי שלא יפעילו את הטיימר בזמן הקלדה או יפעילו במקביל כפתור שמקבל מיקוד. חזור למסך הכתיבה ולחץ באזור שאינו שדה קלט. אם הוגדר צירוף, יש ללחוץ בדיוק את מקשי העזר שנשמרו.

<a id="desktop-copilot"></a>
### אפשר להשתמש במקש Copilot או בצירוף כמו Ctrl+Shift+F23?

אפשר להגדיר את הצירוף אם מערכת ההפעלה מעבירה אותו לתוכנה. אם Windows מפעיל פעולה משלו ולוכד את המקש, התוכנה אינה מקבלת את הלחיצה. במקרה כזה בחר קיצור אחר שמגיע למסך הכתיבה.

<a id="desktop-floating"></a>
### מהו החלון הצף ב־Windows?

כפתור „חלון צף” במסך הבית מאפשר לעבוד בחלון קטן ונגיש של הטיימר בזמן שימוש במחשב. זהו אותו מצב כתיבה ואותם נתונים, לא טיימר נוסף. גם בו יש להקפיד על בחירת פרויקט, הפסקה וסיום כתיבה.

## התקנה, עדכון ופתרון תקלות

<a id="support-version"></a>
### איך בודקים איזו גרסה מותקנת?

פתח „הגדרות” ואז „אודות” ובדוק את מספר הגרסה. אם אפשרות מהמדריך אינה מופיעה, בדוק תחילה אם הגרסה שלך קודמת ל־0.6.0. המסמך מתאר את גרסת הפיתוח הנוכחית ולא מעיד שכל האפשרויות כבר פורסמו להורדה.

<a id="support-install-windows"></a>
### הורדתי ZIP ל־Windows. איך פותחים את התוכנה?

חלץ את כל החבילה לתיקייה והפעל את קובץ התוכנה מתוכה. אל תעתיק רק את קובץ ה־EXE: הוא זקוק גם לקבצים ולתיקיות שבחבילה. אם מופיעה שגיאה על ספרייה חסרה, בדוק תחילה שהחילוץ הושלם ושהחבילה נשמרה בשלמותה.

<a id="support-update"></a>
### איך מעדכנים מתוך התוכנה?

בגרסה הכוללת את המנגנון פתח „הגדרות” ובחר „בדוק ועדכן”. אם נמצאה גרסה, בדוק את הפרטים ואשר „הורד ועדכן”. ב־Android יש להשלים את אישור ההתקנה במסך המערכת; ב־Windows התוכנה נסגרת ונפתחת כחלק מהעדכון. לפני העדכון סיים ושמור עבודה וצור גיבוי.

<a id="support-auto-update"></a>
### האם התוכנה בודקת או מתקינה עדכונים בעצמה?

לא. בדיקת העדכונים מתחילה ביוזמת המשתמש, והורדת עדכון דורשת אישור נוסף. אין בדיקת עדכונים אוטומטית בכל פתיחה. ב־Android ההתקנה דורשת גם את אישור מערכת ההפעלה.

<a id="support-update-network"></a>
### בדיקת העדכון או ההורדה נכשלו. מה עושים?

קרא את ההודעה: חיבור חסר, סינון רשת, בעיית תעודה, חבילה חסרה וכשל אימות הם מצבים שונים. בדוק חיבור ונסה שוב דרך רשת מורשית מתאימה. קובץ שלא עבר אימות אינו מיועד להתקנה. אם הבעיה חוזרת, דווח את הנוסח המדויק ואת גרסת התוכנה.

<a id="support-android-install"></a>
### Android מבקש הרשאת התקנה או מסרב לעדכן. למה?

ייתכן שצריך לאשר התקנה ממקור זה במסך המערכת. אם המתקין עדיין מסרב, יכולה להיות אי־התאמה בין חבילת העדכון להתקנה הקיימת. אל תסיר את התוכנה כדי לנסות לפתור זאת לפני שיש גיבוי בדוק; שמור את הודעת המערכת ופנה לבירור.

<a id="support-notifications"></a>
### התראות אינן מגיעות או מגיעות באיחור. מה לבדוק?

בדוק שההתראה הרצויה מופעלת בתוכנה. ב־Android בדוק גם הרשאת התראות והרשאת „התראות ותזכורות”, אם נדרשת במכשיר, וכן הגבלות מערכת על האפליקציה. ב־Windows אל תסתמך על התראת שעת סיום כשהתוכנה סגורה, משום שהיא מוצגת בתוך התוכנה.

<a id="support-sound"></a>
### המטרונום או צליל הסיום אינם נשמעים. מה לבדוק?

בדוק שהאפשרות המתאימה מופעלת, שהעוצמה בתוכנה ובמכשיר אינה אפס ושיציאת השמע הרצויה פעילה. נסה את כפתור בדיקת הצליל. המטרונום נשמע רק בזמן כתיבה פעילה. אם בדיקת הצליל נכשלת, ציין בדיווח אם מדובר ב־Android או ב־Windows ובאיזו גרסה.

<a id="support-missing-record"></a>
### רשומה ששמרתי אינה מופיעה בסיכום. איך מחפשים אותה?

בדוק את הפרויקט, היום והחודש שנבחרו ואת הגדרת מעבר היום. חפש ברשומות הפרויקט ולא רק בסיכום היומי. בדוק אם זו השלמת עבר ללא תאריך, עבודה פסולה או רשומה שנמחקה לסל. אם הטופס עדיין פתוח או מופיעה הודעת שגיאה, ייתכן שהשמירה לא הושלמה.

<a id="support-storage"></a>
### הופיעה שגיאת אחסון או שמירה. מה לעשות קודם?

קרא את ההודעה והשאר את המסך פתוח כשנאמר שהשמירה לא התחילה. בדוק מקום פנוי וזמינות אחסון ונסה שוב. בטופס הזנה עשויה להישמר טיוטת התאוששות, אך אין להניח שכל מסך שומר טיוטה. אם חסרים נתונים, שמור בנפרד גיבויים קיימים לפני ניסיונות איפוס או שחזור.

<a id="support-backup-unreadable"></a>
### למה קובץ גיבוי אינו נפתח או שחלק מהרשומות לא נקראות?

ייתכן שהקובץ אינו גיבוי מתאים, נפגם, נוצר בגרסה חדשה יותר או מכיל רשומות שהגרסה הנוכחית אינה מכירה. שמור את הקובץ המקורי, קרא את הודעת התצוגה המקדימה ונסה בגרסה תואמת. אל תשנה ידנית את תוכן הגיבוי: שינוי כזה עלול לפגוע בבדיקת השלמות וביכולת השחזור.

<a id="support-journal-rows"></a>
### הזנה אחת מופיעה בכמה שורות ביומן. האם זו כפילות?

מקטעים של אותה הזנה באותו יום ובאותו פרויקט מקובצים לפי מזהה ההזנה ומוצגים בשורה אחת עם סכום זמן הכתיבה. רישומים ישנים ללא מזהה נשארים שורות עצמאיות; גם הזנות נפרדות אינן מאוחדות לפי דמיון בטקסט. אפשר לערוך שורה מהיומן או לפתוח את הטופס המלא.

<a id="support-report"></a>
### אילו פרטים לשלוח כשמדווחים על בעיה?

ציין גרסת תוכנה, סוג מכשיר ומערכת הפעלה, סוג פרויקט, מצב חכם או רגיל ומה עשית לפני התקלה. הוסף מה ציפית לראות, מה התקבל ואת נוסח השגיאה. צילום מסך מועיל אם אין בו מידע שאינך רוצה לשתף. מסור קובץ גיבוי רק אם הוא נדרש ולאחר בדיקת המידע האישי שבו.

<a id="support-contact"></a>
### איפה מוצאים את דף הפרויקט כדי לדווח או להציע שיפור?

במסך „אודות” מופיעים קישורים לאתר האפליקציה ולמאגר GitHub שלה. אפשר להשתמש בדף הפרויקט לצורך דיווח או פנייה למפתח בדרך שבה אתה בקשר עמו. הצעת שיפור תהיה ברורה יותר אם תתאר משימה מעשית שהיית רוצה לבצע ודוגמה לתוצאה הרצויה.
